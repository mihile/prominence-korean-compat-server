# give my trident back

Minecraft **1.20.1 / Fabric / Java 17 이상** 전용 서버 모드. Fabric API가 필요하며 클라이언트에는 설치하지 않습니다.

## 동작

플레이어가 실제로 던진 지원 무기가 공허로 떨어지면, 원래 투사체를 주인 곁으로 회수하고 **그 무기의 기존 획득 처리**로 인벤토리에 돌려줍니다. 새 무기 아이템을 생성하거나 NBT를 재구성해 지급하지 않습니다. 이름·인챈트·내구도·고유 속성은 기존 투사체가 가진 아이템으로 처리합니다.

기본 기준은 `현재 차원의 건축 최저 높이 - 8`보다 낮은 위치입니다. 엔드는 Y < -8, 일반 오버월드는 Y < -72입니다. 바닐라 공허 삭제 지점까지 기다리지 않고 개별 투사체의 원래 tick이 실행되기 전에 구조합니다.

**지원 대상**

- 플레이어가 던진 바닐라 삼지창 및 해당 클래스를 사용하는 삼지창. 기본적으로 충성 인챈트가 없어도 보호합니다.
- Simply Swords 1.70.2의 실제 `ThrownSwordEntity` 계열 무기, 특히 **Livyatan(리비아탄)**. `nonReturning` 공격용 복제 투사체는 제외합니다.
- Soulslike Weaponry 1.3.1의 `ReturningProjectile` 계열 **Leviathan Axe, Mjolnir**. 무기를 소모하지 않고 발사하는 Draupnir Spear는 제외합니다.

현재 설치된 버전의 실제 JAR를 대조했습니다. 다른 모드의 투사체를 이름이나 외형만으로 자동 추측해 반환하지 않습니다. Botania/Aquamirae의 차크람처럼 다른 생성·반환 경로를 쓰는 투사체, 일반 화살, 마법 이펙트, Q로 버린 아이템은 대상이 아닙니다. 몹이 던진 무기도 반환 아이템을 생성하지 않습니다.

## 가득 찬 인벤토리·오프라인·사망

- 인벤토리가 가득 차면 무기를 바닥 아이템으로 떨어뜨리지 않고 **원래 투사체를 주인 곁에 보존**합니다. 슬롯이 생기면 기존 획득 처리를 다시 시도합니다. 대기 중 공격/중력/자연 삭제 처리를 실행하지 않습니다.
- 구조 중인 투사체는 원래 소유자 UUID와 일치하는 플레이어만 획득할 수 있습니다. 인벤토리가 가득 차 대기하는 동안 다른 플레이어가 먼저 획득하지 못하게 합니다.
- 주인이 죽었거나 관전자이거나 공허에 있는 동안은 안전한 반환을 기다립니다. 안전한 위치에 살아 있는 주인을 찾으면 회수합니다.
- 주인이 다른 차원에 있으면 Fabric의 직접 좌표 이동으로 주인 곁에 전달합니다. 이때 포털이나 엔드 발판을 만들지 않습니다. 원래 투사체가 교체되면 교체된 개체만 사용합니다.
- 플레이어 소유자 UUID·구조 중 여부·크리에이티브 출처를 투사체 NBT에 저장하므로 정상 저장과 재로딩을 지원합니다. 이 NBT에는 무기 아이템 복사본을 보관하지 않습니다.
- **크리에이티브에서 던진 무기는 원본이 인벤토리에서 제거되지 않습니다.** 공허의 투사체만 제거하고 아이템을 추가 지급하지 않습니다. 던진 뒤 게임 모드가 바뀌어도 출처를 유지합니다.
- 복제 투사체 구분은 별도 NBT에도 남겨, 원래 모드가 재로딩 때 해당 플래그를 누락해도 이 모드가 복제 무기를 구조하지 않도록 합니다.

청크를 강제로 로드하거나 플레이어 파일을 오프라인으로 수정하지 않습니다. 따라서 주인이 접속을 끊어 투사체 청크도 언로드되면 **그 청크가 다시 로드되어야** 반환 처리가 재개됩니다. 설치 전에 생성되어 소유자를 확인한 적이 없는 투사체는 주인이 오프라인이면 소유자를 임의로 추정하지 않습니다. 이미 공허에서 삭제된 무기를 복구하는 기능은 아닙니다.

## 실행 중 설정

OP 권한 2 이상 또는 서버 콘솔에서 사용합니다. 변경은 즉시 적용하고 `config/give-my-trident-back.json`에 저장합니다. 콘솔에서는 `/`를 생략합니다.

설정 명령은 **기능명 · 이전 값 → 적용 값 · 기본값**을 표시합니다. 예: `/gmtb depth 16` → `회수 기준 깊이 (건축 최저 높이 아래): 이전 8블록 → 적용 16블록 (기본: 8블록)`. 같은 값을 다시 입력해도 확인 메시지를 표시합니다. `status`는 현재 값과 기본값을, `reload`는 변경 내역을 보여줍니다. 기본값은 모드 출고값입니다.

| 명령어 | 기능 |
|---|---|
| `/gmtb` 또는 `/gmtb status` | 설정과 이번 실행의 구조 시작 횟수 |
| `/gmtb enabled false` | 새 구조 시작 끄기. 이미 구조 중인 무기는 계속 보호 |
| `/gmtb enabled true` | 켜기 |
| `/gmtb loyalty true` | 삼지창에 한해 충성 인챈트가 있어야 보호 |
| `/gmtb loyalty false` | 충성 없는 삼지창도 보호 (기본값) |
| `/gmtb depth 8` | 건축 최저 높이보다 몇 블록 아래에서 구조할지 설정, 0~48 |
| `/gmtb reload` | 수동 수정한 JSON을 검증 후 불러오기 |

## 설치·업데이트

현재 이 기능은 서버의 `mods/prominence-korean-compat-1.0.0.jar`에 통합되어 있습니다. 별도의 give-my-trident-back JAR를 함께 설치하지 않습니다. 클라이언트에는 추가 설치가 필요 없습니다.

설정과 `/gmtb` 명령어는 위 설명대로 유지됩니다. `config/give-my-trident-back.json`은 기존 파일을 그대로 사용합니다. GitHub의 독립 저장소는 사용자 요청으로 삭제하고 로컬 소스와 저장소 백업을 보존합니다.

로컬 소스에서 다시 통합하려면 서버 종료 후 아래 명령을 사용합니다. 현재 호환 JAR의 다른 기능을 보존하며 기존 파일을 백업합니다. 종료 확인 인자는 사용자가 종료했다고 확인한 경우에만 지정합니다.

```powershell
python integrate.py --apply --shutdown-confirmed
```

## 빌드

빌드에는 **JDK 21**이 필요합니다. 모듈 JAR는 Java 17 이상에서 실행됩니다. 빌드된 모듈은 integrate.py로 호환 JAR에 통합합니다. Gradle Wrapper가 포함되어 있어 Gradle을 따로 설치할 필요는 없습니다.

Windows:

```bat
gradlew.bat build
```

Linux / macOS:

```sh
./gradlew build
```

- 통합 입력용 모듈 JAR (별도 설치하지 않음): `build/libs/give-my-trident-back-1.0.1+1.20.1.jar`
- 소스 JAR: `build/libs/give-my-trident-back-1.0.1+1.20.1-sources.jar`
- 테스트만 실행: Windows는 `gradlew.bat test`, Linux/macOS는 `./gradlew test`
- 테스트 결과: `build/reports/tests/test/index.html`

`build`에는 테스트가 포함됩니다. 정책·설정·소유자 저장·명령어 파싱 및 설치된 Minecraft/모드의 바이트코드 대상을 검사합니다. 로컬 대상 JAR이 없으면 해당 바이트코드 검사는 건너뜁니다. 테스트는 실제 Mixin 변환·서버 기동·게임 내 투척 검수를 대신하지 않습니다.

## 제거

롤백은 서버 종료 후 통합 전 호환 JAR와 별도 회수 모드 JAR를 백업에서 함께 복원합니다. 호환 JAR 전체를 삭제하면 다른 패치도 제거되므로 삭제하지 않습니다. 구조 대기 중인 투사체가 있으면 일반 공허 처리가 다시 적용될 수 있으므로, 플레이 중 모드를 제거하기 전에는 해당 무기를 먼저 획득해야 합니다.
