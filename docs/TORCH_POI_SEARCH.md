# Conservative Magnum Torch POI search

Build2026110309 narrows MagnumTorch8.0.2's candidate POI query without changing configured spawn protection. A server JFR recorded approximately2.79seconds of server-thread CompletableFuture.join waiting under MobSpawningHandler.isSpawnCancelled -> Lithium POI traversal -> native POI column loading. This is a proven synchronous wait path, not proof that the entire7.73-second backlog was caused by the torch.

The native code uses `ceil(max(horizontal, vertical) * 1.7320508076)` as a spherical candidate radius for every shape. The final predicate separately checks the configured ellipsoid, cylinder or cuboid. The patch redirects only the candidate query and forwards the original POI type predicate, position predicate, center and occupation. Spawn reason/category/whitelist/blacklist and the final native anyMatch predicate remain unchanged.

For positive ranges up to4,096, the conservative enclosing sphere is max(h,v) for ellipsoids, hypot(h,v) for cylinders, sqrt(2*h*h+v*v) for cuboids. One extra block is added outside ceil(bound) to cover float rounding in the native ellipsoid predicate, and the original radius is never increased. Null/zero/negative/extreme configurations use the original query unchanged. There is no cached spawn result, so configuration and POI placement/removal continue to be read through the native path.
